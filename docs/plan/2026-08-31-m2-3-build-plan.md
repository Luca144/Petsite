# M2.3 — One page per creature: the build plan

**Status: awaiting sign-off. No code has been written.**

The build plan calls this "the single most important screen in the panel",
and M2's definition of done hangs on it: *the artist adds a complete new
species — every stage, stats, blurbs, library entry — alone, start to
finish.* This is the mandatory written plan of CLAUDE.md §7 (the increment
touches panel permissions and the species schema), with the three security
questions answered and the open questions gathered at the end.

---

## 1. What exists today, honestly

- A species is 10 columns (`species`): slug, name, one `flavour_text`,
  starter/adoptable flags, gem price, two taste links. **No draft concept,
  no per-stage text, no art columns, no versions.**
- **Sprites are a filename convention**, `/assets/creatures/{slug}/{stage}.gif`,
  and that convention is **written out inline in six different templates**
  (creature page, card, moment, keepsake, profile, shop). Uploaded art
  (M2.2) is a parallel world nothing links to yet.
- Species are read at exactly six call sites, all through
  `SpeciesRepository` — which is read-only by design and says so. M2.3
  breaks that assumption deliberately.
- Three seeded species exist (foxlen, mossling, pebblewing), live on
  production, with repo art.

## 2. What M2.3 builds

### The data

One migration (**named in the handover's first paragraph, as always**):

- `species` gains: `status` ('draft'/'published' — the three live species
  are backfilled to 'published'), `updated_at`, `lore` (library text),
  `library_art_id` (FK → art_files, SET NULL).
- **`species_stages`** — one row per (species, stage): `sprite_art_id`
  (FK → art_files, SET NULL) and `blurb` (NULL). Stage names are validated
  against the config's `stage_start_levels` keys, so a fourth stage added
  in config automatically appears on the screen — the screen iterates,
  never hardcodes three.
- **`species_versions`** — the undo: `species_id`, `snapshot` (JSON of the
  species fields plus its stages' art ids and blurbs), `saved_by_user_id`,
  `created_at`. Written on every save, pruned to the newest N (config,
  proposed 20). Revert = restore a snapshot. Art bytes are never part of a
  version — they are content-addressed in the store and a snapshot only
  references them, which is what makes versions cheap.

### One sprite resolver, ending the six copies

`Species` learns the art-store world: a single `spriteUrlFor(stage)` that
returns the art-store URL when a `sprite_art_id` is linked and **falls back
to the old convention path** when not — so the three existing species keep
working untouched, and a new species never needs repo art at all. All six
inline template copies are replaced by calls to this one method. That
refactor is not a nicety; it IS the "one-click art replacement updates
every reference" promise — after it, changing a stage's picture is one
update in one table, and the content-hash URLs from M2.2 defeat every
cache for free. `PixelArt::displaySize` learns to read art-store files
from the volume path as well as `public/`.

(An optional `bin/import-repo-art.php` can later move the three old
species' nine GIFs into the art store and link them; until then the
fallback carries them. Nothing depends on when that happens.)

### Draft and published — who sees what

The survey's key asymmetry, made explicit:

- `findById()` / `all()` stay **unfiltered**: players already OWN creatures
  of a species, and a draft edit must never make someone's live creature
  render as "Unknown species".
- `findAdoptable()` and `findStarters()` additionally require
  `status = 'published'` — so no draft can be **acquired**: not bought
  (the shop re-derives its allow-list on purchase already), not granted as
  a starter, not found while exploring.
- The shop page lists published-and-adoptable only (it already goes
  through `findAdoptable()`).

Publishing has a **minimum**: a species may not publish until every stage
has a sprite and the species has a name and flavour text (proposed rule —
question 2 below). The refusal names exactly what is missing, per stage.
Unpublishing (back to draft) is allowed and explained in plain words on
the button: existing creatures keep living and rendering; the species just
leaves the shop and the starter pool.

### The screens (Artist role; owner passes everything)

- **`/admin/creatures`** — every species as a card: sprite, name, a
  status chip ("draft" / "published" as words), what's missing if draft.
  Plus "start a new species" (name in, slug generated, born as draft).
- **`/admin/creatures/{id}`** — THE page. Sections, each its own small
  form so "save as you go" is literal (Post/Redirect/Get like everything):
  names & words (name, flavour text, lore), one card per stage (current
  sprite, "choose a picture" link, blurb), library art, numbers & flags
  (gem price, adoptable, starter, the two taste items — picked from
  searchable tiles, never a dropdown), and the version list with one
  "restore this version" button per row.
- **`/admin/creatures/{id}/sprite/{stage}`** — the picker: the art
  store's sprites (`ArtKind::Sprite`, and `Library` for the library slot)
  as a tappable grid; choosing links the art and returns. No modal, no JS
  framework — a page, like everything else.
- **`/admin/creatures/{id}/preview`** — the real creature-page template
  rendered with a stand-in creature of that species, a stage switcher
  (baby/juvenile/adult as toggle buttons), viewable at any width. This is
  the page the artist checks on their phone before publishing.
- Every mutating action audited (new `AuditAction` cases:
  `species.created`, `species.saved`, `species.published`,
  `species.unpublished`, `species.reverted`) with before/after snapshots —
  exactly the hook the audit enum's docblock reserved for M2.3.

### The guard M2.2 promised

`ArtService::delete()` gains the reference check: a picture linked as any
species' stage sprite or library art **refuses deletion**, naming the
species ("Bramble's adult stage uses this picture — unlink it there
first"). Tested both ways.

## 3. The three security questions

**1. Who is allowed, and how is that enforced?** Artist or Owner, through
the same `AdminGate` every admin route is registered through — role read
fresh per request, door + second factor required — plus CSRF on every form
and a save rate limit. There is no per-species ownership (the content is
the site's, not one artist's), so the gate IS the authorisation; the
services validate every value against allow-lists (stage names from
config, status from a two-value list, art ids that must exist and be of
the right kind) and never trust an id from the form beyond looking it up.

**2. Worst case from a hostile request?**
- *Acquiring a draft* — buying, starter, exploration: all three run
  through the two filtered repository methods, and the purchase re-derives
  its allow-list server-side; a posted `species_id` of a draft is refused.
  Each has an explicit refusal test.
- *Hostile text in species fields* — name/flavour/blurbs/lore render on
  public pages; author is staff behind 2FA, but escaping-on-output is
  still absolute (Plates default, tests include a script-tag name),
  lengths are capped, and the slug is locked to `[a-z0-9-]` (it appears
  in URLs and the legacy path convention).
- *Linking the wrong picture* — art ids are looked up and must be of the
  allowed kind; a deleted art id becomes NULL (SET NULL) and the screen
  shows "missing picture", never a broken reference.
- *Reverting to a poisoned snapshot* — snapshots are server-written JSON,
  never accepted from the browser; revert takes a version ID, looks it up,
  and applies only whitelisted fields from it.
- *Racing saves* — last write wins per section (two artists editing one
  species at once is a people-problem two-people teams solve by talking),
  but every save is versioned and audited, so nothing is ever LOST to a
  race. Written down here so it is a known, accepted trade rather than a
  surprise.
- *Publish/unpublish flapping* — rate-limited with saves; each transition
  audited.

**3. What do the tests refuse?** Draft species: absent from the shop page,
purchase POST refused, never granted as starter, never found exploring —
each its own test. Publish refused with the exact missing pieces named;
publish allowed once complete. Revert restores fields and stage links and
is audited. Slug collisions and bad characters refused. A referenced
picture refuses deletion; an unreferenced one deletes. Script-tag species
name renders inert on the creature page. The `AdminGateTest` matrix grows
the new routes (moderator/coder refused, artist admitted). Existing-
creature rendering with a draft species stays intact (the asymmetry,
pinned). Smoke test: create a species through the real forms, link
sprites from the real art store, preview it, publish it, buy one, see it
on its creature page.

## 4. Scale and slices

For 3–50 species everything here is trivial load; the list screen is one
query, the editor a handful. Versions are pruned so the table cannot grow
unbounded. The work lands as one increment but in reviewable slices:
schema + repository writes + list/editor basics; then sprite pickers +
the resolver refactor across the six templates; then publish rules,
preview, versions. One handover at the end, as always.

## 5. Open questions — decided by you, not by me

1. **Alternate forms: defer to M5?** The plan text names them in M2.3, but
   no game mechanic anywhere assigns or displays a form — they would be
   dead data behind extra UI on the panel's most important screen. The
   library milestone (M5) is where forms first *appear* ("alternate forms,
   shown here too"), and adding a `form` column to `species_stages` then
   is one small migration. Recommendation: defer, and note it in
   decisions.md so it reads as chosen, not forgotten. (This is also the
   kind of scope call Skerro may want a voice in.)
2. **The publish minimum.** Proposed: every stage has a sprite; name and
   flavour text present; blurbs, lore and library art optional (the
   library doesn't exist yet). Stricter (blurbs required) or looser?
3. **Version history depth**: propose keeping the newest 20 per species.
4. **Unpublish**: proposed allowed (see §2). Veto if you'd rather a
   published species be permanent.
