# M2.9 — The stats page (build plan)

*2026-09-01. The last M2 increment before the checkpoint. Proceeding
under the standing arrangement.*

## What this builds

One read-only screen — Panel → **Stats** — that replaces the manually
kept spreadsheet: what is being adopted, bought and visited, how much
currency exists, which areas get used (build plan M2.9). It turns
balancing from guesswork into a decision, and it is the artist's
marketing information — so it belongs to Role::Artist (and the Owner).

**Aggregate only, by design.** The build plan's own words: this is about
the game's health, not about surveilling individuals. No per-player
numbers, no player names, no "most active player" lists — the only names
on the page are CONTENT names (species, areas, items), which the artist
made. The one number about people is how many there are.

The numbers (all from existing tables; no migration):
- **Players**: total accounts; new this week; active this week (logged in).
- **Creatures**: total in the world; new this week; per species — the
  adoption picture, and the first honest "nobody picks the Mossling" signal.
- **Care**: pets given this week; guestbook entries signed this week.
- **Economy**: gems in circulation (the sum of every purse); items held
  across all pockets; what the shop sold this week is NOT knowable yet
  (no order ledger exists — said on the page honestly rather than
  approximated; a ledger is an M8+ decision).
- **Areas**: searches this week per area — which places get used.

## The three security questions (CLAUDE.md §7)

1. **Who, and how enforced?** `GET /admin/stats`, Role::Artist via the
   gate, in the `AdminGateTest` matrix. Read-only; no input at all.
2. **Worst a malicious actor could do?** Nothing to write, no ids to
   tamper with. The information itself is the risk surface: per-player
   data would make this a surveillance screen, so the service exposes
   aggregates only — enforced by what the queries SELECT (counts and
   sums, never user rows), which the test pins by asserting no player
   name appears on the rendered page.
3. **What do the tests prove?** The matrix refuses non-Artists; a
   fixture world (players, creatures, pettings, visits) produces the
   right counts; a player's username never appears in the page body.

## Scaling note

Eight aggregate queries per view, on tables counted in thousands at
most. COUNT/SUM with the existing indexes is milliseconds; if the site
ever has enough rows for this to hurt, cache the result for an hour —
the numbers are a weather report, not a ticker.
