## What this builds

One generated screen — Panel → **Unfinished** — that answers "what still
needs doing?" so nobody holds that list in their head (build plan M2.6).
It reads; it never writes. Two tiers, because two different questions:

1. **Drafts that cannot publish yet** — each draft species/item/shop/area,
   with its missing pieces named in the editors' own words (the four
   `missingForPublish()` methods are reused verbatim, so this screen and
   the publish buttons can never disagree).
2. **Published, but missing a nicety** — live content the site renders
   with a fallback: an item wearing its category's icon instead of its
   own, an area scene on the glow placeholder, a shop whose keeper has no
   greeting, a species without lore/library art. Nothing here is wrong —
   the screen says so — but it is the artist's to-do list.

Every row links straight to the editor page that fixes it. An empty list
says something warm, not nothing.

## The three security questions (CLAUDE.md §7)

1. **Who is allowed, and how is it enforced?** Artist role (and Owner, as
   everywhere). One new route, `GET /admin/unfinished`, registered through
   `$adminGate->protect(Role::Artist, ...)` — the same chokepoint as every
   panel route, authorised on every request. It joins the `AdminGateTest`
   matrix like all its siblings.
2. **Worst a malicious user could do?** The screen is read-only and takes
   no input at all (no query string, no ids) — there is nothing to inject
   or replay. The information itself (which content is unfinished,
   including DRAFTS invisible to players) is panel-only knowledge; the
   gate is what keeps it that way, which is exactly what the matrix test
   proves. No new writes ⇒ no new audit actions.
3. **What do the tests prove?** The gate matrix refuses every non-Artist
   on the new route; a unit-style integration test creates one of each
   incompleteness (draft species missing a stage picture, item with no
   icon of its own, area with no background, shop with no greeting),
   sees each detected, fixes each, and sees each cleared — the build
   plan's own test sentence.

## Shape

- `src/Admin/UnfinishedListService` — asks the four repositories for
  everything, the four editor services what blocks publishing, and adds
  the nicety checks. Returns plain arrays the template prints.
- `AdminUnfinishedController` (~40 lines) + `pages/admin-unfinished.php`.
- A tile on the panel home ("Unfinished — what still needs a hand").
- No migration. No config. No JavaScript.

## Scaling note

Four `all()` calls plus per-species stage checks — the same queries the
four list screens already run, on content counted in dozens. Fine to
thousands of rows; if content ever reaches that size, the fix is caching
the counts, not restructuring.
